# EACL 2027 response draft

We thank both reviewers for their comments on the model family, its practical value, and the limitations of the evaluation. We have clarified the contributions, expanded the training and serving descriptions, and corrected the multilingual aggregation.

**Novelty and scope.** We removed the claim to the first general-purpose MoE embedding encoder and added Nomic Embed v2 (Nussbaum and Duderstadt, 2025, arXiv:2502.07972) and MoEE (Li and Zhou, ICLR 2025). We distinguish MoEE's training-free embedding construction from our trained bidirectional encoder. The contribution is the released model family and its quality and throughput evaluation. We also removed the general claim “without sacrificing embedding quality.” Qwen3-Embedding-4B scores higher than our MoE model on English, multilingual, and code tasks. Differences in backbone, capacity, embedding dimension, and runtime settings prevent attributing the throughput difference solely to sparsity.

**Serving benchmark.** Each run used one H100 80GB HBM3 GPU, BF16, vLLM 0.24.0, PyTorch 2.11.0+cu129, CUDA runtime 12.9, Transformers 5.13.0, and Python 3.12.13. For each setting, three warm-up calls preceded seven timed synchronous embedding calls. Throughput is batch size times input length divided by median call duration. Inputs are synthetic random token IDs of exact length, without padding; model loading, tokenization, and input generation are excluded. Appendix C specifies the input generator, timing boundaries, pooling, and engine settings, including the MoE patches. The full external baseline name is `nvidia/llama-embed-nemotron-8b`.

The original five-configuration throughput table is retained. MoE reaches 112.6k/114.5k/102.3k tokens/s at 512/1024/2048 tokens, compared with 87.9k/91.5k/90.4k for 3B, giving 28%/25%/13% higher throughput. It is the fastest of the five configurations shown. The 480M model is not included in this comparison. Latency and peak GPU memory are not reported. The 0.97/6.30/20.95 decimal-GB estimates for 480M/3B/MoE describe full 16-bit weight storage and exclude other runtime memory.

**Compact model and FRIDA.** We now emphasize comparable Russian benchmark performance with a smaller model: the 480M encoder scores 70.96 versus FRIDA's 70.95 with approximately 42% fewer parameters, using the reported sizes of 480M and 823M. The same encoder also supports English, multilingual, and code embedding tasks. The scores were obtained under different evaluation settings. Here, comparable refers to the observed benchmark scores; statistical equivalence has not been tested. The claim is stated in the abstract, a separate contribution, and the conclusion. We make no claim about FRIDA's unreported multilingual capabilities.

**Training data.** We corrected the original description: embedding training uses open-source Nemotron and KaLM data, while GigaChat backbone pre-training is proprietary. Appendix B identifies HIT-TMG/KaLM-embedding-pretrain-data, KaLM-Embedding/KaLM-embedding-finetuning-data, and nvidia/embed-nemotron-dataset-v1. We confirm that embedding-training and evaluation examples do not overlap; documentation of the checking procedure is unavailable, and no new overlap audit is claimed.

Appendix B reports dataset sizes and consumed-sample counts for selected 480M development runs. For example, KaLM pre-training has 299,034,744 prepared rows and 299,024,384 consumed samples; a multitask run has 2,439,873 prepared rows and 7,317,504 consumed samples over three epochs. These are counts for individual runs, not unique-example totals or the composition of the final models. The table includes Giga/F2LLM pre-training and four fine-tuning recipes. It also distinguishes the F2LLM pre-training global batch of 1024 from the Giga/KaLM value of 16,384. Language proportions, exact input dataset versions, and the complete merging history remain unavailable.

**Architecture and teacher.** The dense encoders use the Qwen3 architecture but are initialized from proprietary GigaChat checkpoints, not public Qwen3 checkpoints of those sizes. Appendix A gives the layer dimensions, expert configuration, and parameter-counting convention, which yields approximately 1.63B active parameters per token. The released model name remains “10B-A1.8B.” The teacher for the 480M model is a 10B MoE encoder. Its query and candidate embeddings are precomputed; the student matches similarity distributions over eight candidates with KL weight 0.3 and temperature 0.05. The exact teacher versions and model-merging procedures are not fully documented. The released router settings do not specify the training-time balancing loss, capacity limits, or token-dropping policy. The release model cards specify the MIT license.

**Distillation comparison.** We removed “consistent gains” and relabelled Table 7 as a descriptive comparison. The +0.09/+0.12/+0.22 differences come from single training runs with different initialization checkpoints and microbatch sizes, despite the same global batch size. The available initialization files differ in 308 of 310 tensors, but their exact versions at training time cannot be verified. The comparison therefore does not isolate the effect of KD. Multilingual results for the no-KD model and results from independent training repetitions are unavailable. A unified evaluation has only passed CPU preflight and is not reported as completed. A separate KaLM-12B-teacher fine-tuning pair is not used as evidence for the final 10B-teacher models.

**Multilingual correction.** We replaced the original 480M value 56.97 with 56.80. An earlier notebook can reuse another task's score when it encounters the length-specific splits of LEMBPasskeyRetrieval. Replaying the stored file order gives 56.970884; averaging all 131 tasks using the fixed list of 46,933 subset/split scores gives 56.799822. This replay shows how the earlier value can arise, but does not establish how the paper's original value was computed. Appendix E describes the corrected aggregation and its limitations. The task results were produced with different MTEB versions and cannot be verified against a specific model revision; 56.80 is therefore marked as a recomputed value, not a new inference result or a complete public leaderboard score. The resulting gap to 3B is approximately 7.09 points. The 3B/MoE aggregates agree with the public 63.89/65.64, and all selected scores for those two models match the public results.

**Russian aggregation and references.** The original 480M Russian 70.98 and public 70.96 are computed from identical task-level results. Selecting test splits when available gives 70.978526; averaging validation and test for the two MASSIVE tasks gives 70.959130 (Appendix D). Both rows of Table 7 use the same test-preferred rule. The previous publication is available at ACL Anthology, DOI [10.18653/v1/2025.bsnlp-1.3](https://aclanthology.org/2025.bsnlp-1.3/); its authors and bibliographic metadata have been corrected. We also corrected Wen-tau Yih, model names, and the unexplained release suffix.
