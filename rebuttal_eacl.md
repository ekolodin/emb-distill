We thank both reviewers. The revised manuscript clarifies the contribution, expands the methods, and corrects score aggregation.

**Contribution and quality.** We removed the first-MoE-encoder claim and added Nomic Embed v2 (arXiv:2502.07972) and MoEE (Li and Zhou, ICLR 2025). We also removed “without sacrificing embedding quality”: Qwen3-Embedding-4B scores higher on English, multilingual, and code tasks. Our contribution is the released model family and its measured quality and throughput trade-offs. Without matched dense controls, differences in backbones, dimensions, and runtime settings prevent attributing the speed advantage solely to sparsity.

**Compact model.** The key result is comparable observed Russian MTEB scores with fewer parameters: 480M scores 70.96 versus FRIDA's 70.95, with approximately 42% fewer parameters (480M vs. 823M). The 480M model also supports English, multilingual, and code tasks. This is a contextual comparison across evaluation settings, not a statistically established win or equivalence claim; we make no claim about FRIDA's multilingual capabilities.

**Serving.** Runs used one H100 80GB HBM3, BF16, batch 16, vLLM 0.24.0, PyTorch 2.11.0+cu129, CUDA runtime 12.9, Transformers 5.13.0, and Python 3.12.13. Synthetic random token IDs have exact lengths without padding. Three warm-ups precede seven timed synchronous embedding calls; throughput is batch size times input length divided by median call duration, excluding loading, tokenization, and input generation. Appendix C specifies engine settings and MoE patches. The baseline is `nvidia/llama-embed-nemotron-8b`.

MoE throughput is 112.6k/114.5k/102.3k tokens/s at 512/1024/2048 tokens, 28%/25%/13% above dense 3B. The claim is limited to the five configurations shown. We do not report 480M throughput, latency percentiles, or peak GPU memory. Full 16-bit weight storage is 0.97/6.30/20.95 decimal GB for 480M/3B/MoE; these estimates exclude runtime state. The benchmark does not establish production latency or traffic capacity.

**Data.** We corrected the description: embedding training uses open-source Nemotron and KaLM data; proprietary data concern GigaChat backbone pre-training. Appendix B names HIT-TMG/KaLM-embedding-pretrain-data, KaLM-Embedding/KaLM-embedding-finetuning-data, and nvidia/embed-nemotron-dataset-v1. We confirm no overlap between embedding-training and evaluation examples; documentation of the checking procedure is unavailable, and we claim no new overlap audit. Prepared/consumed sample counts are reported for selected development runs, not as final unique-example totals. Final mixture proportions, language shares, and exact input versions remain unavailable.

**Architecture and KD.** Dense models use Qwen3 architectures initialized from proprietary GigaChat checkpoints. Appendix A details released dimensions and routing; the stated counting convention gives approximately 1.63B active parameters, while the release name remains 10B-A1.8B. Training-time balancing loss/coefficient, capacity limits, and token-dropping policy are unavailable. The 480M teacher is a 10B MoE encoder with cached query/candidate embeddings, KL weight 0.3, and KD temperature 0.05. Exact teacher versions and merging history are incompletely documented. Release model cards specify MIT.

We replaced “consistent gains” with a descriptive comparison: +0.09/+0.12/+0.22 come from single runs with different initializations and microbatch sizes, so they do not isolate KD. No independent training repetitions, no-KD multilingual result, or sensitivity study over weight, temperature, or teacher choice is available.
